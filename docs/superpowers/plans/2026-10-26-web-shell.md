# Web shell + Problem page (I-15) Implementation Plan

> **For agentic workers:** test-first where practical. Touch only the owned paths listed in
> ROADMAP I-15. Checkbox (`- [x]`) steps.

**Goal:** an offline React SPA in `web/` with the Problem page (statement, lesson, hints, CodeMirror
editor, Run/Submit, results, topic picker). `dogma serve` serves the build at `/`. Learner state
stays in the API and the workspace file, so the browser holds no truth of its own.

**Architecture:** TanStack Query for server state, a small fetch client, SSE over `fetch` for the
hint stream (POST, so not `EventSource`). API types come from the in-process OpenAPI export.

## Static serving

- [x] `api/static.py`: `mount_spa(app, dist)`. Only when `dist/index.html` exists.
  Existing files under `dist` are served, any other non-`/api` path gets `index.html`, and
  `/api/...` misses stay `API_NOT_FOUND` problems. Traversal outside `dist` is refused.
- [x] `api/app.py`: `create_app(..., web_dist=DEFAULT_WEB_DIST)`. The default is the code repo's
  `web/dist`, not `settings.repo_root`, so a scratch `DOGMA_REPO_ROOT` still serves the UI.
- [x] Same-origin POSTs from the served page carry `Origin: http://<host>:<port>`, which the
  allow-list would refuse. An outer ASGI wrapper in `app.py` drops an `Origin` equal to the
  request's own origin when `Host` is loopback. The Host guard still runs. `middleware.py` is not
  an owned path, so this lives in `app.py` (flagged in the report).
- [x] Tests: `tests/unit/api/test_static.py`. Index at `/`, client route fallback, asset files,
  traversal, API routes unaffected, nothing served without a build.

## Behaviour contracts

- Run and Submit save a dirty buffer first, because the server grades the file on disk.
- Autosave: 800 ms debounce, visible saved/saving/error state, 256 KiB guard (UTF-8 bytes).
- Missing workspace file: seed from `starter`, then PUT once.
- Hints: `reviewed` shows at once, `nudge` streams, `done` replaces it. `unavailable` and `error`
  show calmly. Level 4 needs an explicit checkbox, which sends `confirm_walkthrough`.
- Results: one row per test (mark, public|hidden, name). Public failures show the full message,
  hidden failures show the safe summary. Rejected, timeout, oom and error show the message and
  findings. Recording state is shown subtly.
