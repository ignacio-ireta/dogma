# Local Corpus Retrieval Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the imported notes, lesson content and local paper collection searchable with reliable citations.

**Architecture:** A source scanner feeds a heading/page-aware chunker and a separate
SQLite FTS5 index at `corpus/index.db`. Vendored docmd owns PDF conversion; this
service consumes its Markdown and provenance without importing its Python project.
Search returns typed detached chunks for both CLI display and tutor context.

**Tech Stack:** Python 3.12, stdlib sqlite3/hashlib/subprocess, Pydantic, existing
PyYAML/Typer/Rich, separately managed vendored docmd.

**Spec:** `docs/ARCHITECTURE.md` §4.6, `docs/IMPORT_PLAN.md`,
`docs/superpowers/specs/2026-10-24-learning-sequence-design.md`.

## Global Constraints

- Stay inside the repo; never scan private/, workspace/, var/ or other projects.
- Corpus data and the index stay gitignored; never store learner state in this DB.
- Use `uv run --frozen`; docmd is invoked through its own uv project.
- Keep source/page/heading provenance attached to each chunk.
- No embeddings or model calls; first measure SQLite FTS5/BM25 retrieval.
- Input documents are data and are never executed. Skip escaping symlinks.
- Partial conversion failures are reported without dropping unrelated good sources.

## Review Focus

- FTS punctuation/quotes/operators cannot cause SQL errors or unintended query syntax.
- Deleted sources disappear from retrieval; failed replacements retain the last good index.
- Repeated sync does not duplicate chunks or update unchanged source records.
- Headings that look like page markers inside code fences are not provenance.
- A missing or corrupt index produces a useful domain error, not a traceback.

### Task 1: Source scanning, chunking and search

**Files:** create `src/dogma/corpus/{__init__,models,chunker,index,sync}.py`,
`tests/unit/corpus/`, and `tests/integration/corpus/` fixtures. Add domain codes
to `src/dogma/core/errors.py`; settings-derived paths may be properties in core.

**Interfaces:** frozen `Chunk(source_id: str, path: str, page: int | None,
headings: tuple[str, ...], ordinal: int, text: str, topic_ids: tuple[str, ...])`;
`chunk_markdown(text: str, *, source_id: str, path: str,
topic_ids: tuple[str, ...] = ()) -> tuple[Chunk, ...]`;
`search(settings: Settings, query: str, *, topics: tuple[str, ...] = (),
k: int = 5) -> tuple[SearchHit, ...]`; `SearchHit` includes a Chunk, citation and
BM25 score. `sync_index(settings: Settings) -> SyncReport` returns counts of
added/updated/removed/unchanged sources plus typed per-file issues.

- [ ] Write tests for heading nesting, `### Page N` from docmd, front matter,
  code fences, empty documents and long paragraphs. Chunks target roughly 500
  tokens using a documented deterministic character/word approximation and
  split before heading/page transitions. Never combine different PDF pages.
- [ ] Write fixture index tests for independent hand-expected top hits, literal
  punctuation searches, empty queries, k bounds, topic filters and citations.
- [ ] Implement deterministic source ids: `content:<topic-id>/lesson`,
  `sources:<source-id>/<relative-path>` and `corpus:<source-id>/<relative-path>`.
  Citations expose these ids and page numbers, with repo-relative Markdown paths.
- [ ] Scan Markdown under imported sources and corpus/md; exclude docmd run logs,
  archives and metadata. Include only verified/reviewed content lessons.
  Tag content with its topic id and imported notes with title/alias keyword matches.
- [ ] Use sha256 plus chunker version for incremental updates. Store source and
  chunk rows with external-content or ordinary FTS5 indexing and porter tokenizer.
  Apply each successful source replacement atomically; retain previous chunks on
  read/parse failure. Delete genuinely absent sources and their FTS rows.
- [ ] Tokenize user query into quoted literal terms; parameterize SQL and limit;
  empty-token queries return no hits. Tie-break BM25 results by source/ordinal.
- [ ] Run targeted tests, mypy, ruff and default suite. Expected: pass; record RED/GREEN.

### Task 2: Vendored conversion adapter and CLI

**Files:** create `src/dogma/corpus/convert.py`, `src/dogma/cli/corpus.py`,
`tests/unit/corpus/test_convert.py`, `tests/unit/cli/test_cli_corpus.py`; register
commands in CLI main and update README/ARCHITECTURE through coordinator.

**Interfaces:** `convert_sources(settings: Settings) -> ConversionReport` invokes
docmd for raw-source directories without a shell; `sync_corpus(settings,
*, convert: bool = True) -> CorpusSyncReport` converts then indexes.
CLI `dogma corpus sync [--no-convert]`, `dogma corpus search QUERY [--topic ID]
[--limit N]`; sync exits nonzero for conversion/index issues while printing counts.

- [ ] Test exact adapter argv using a subprocess boundary fake, including paths
  with spaces, missing converter, timeout and docmd nonzero/partial results.
  Documented docmd output structure is in tools/docmd/docs/extraction_contract.md.
- [ ] Invoke `uv run --frozen --project tools/docmd docmd sync RAW --out MD`
  with deterministic output, explicit OCR policy and bounded per-source timeout.
  Inspect vendored CLI for exact flags; do not assume a flag exists. Use a
  timeout suited to batch conversion, and report source-level failures clearly.
- [ ] Add CLI fixture flow: sync twice, search, modify/delete source, sync, search;
  expected hit/citation changes and no duplicate chunks. Verify no writes to var/.
- [ ] Verify a bounded real Markdown-source sync/search. Full PDF conversion runs
  separately with progress and its errors reported; no live model dependency.
- [ ] Independent review, full gate, and roadmap handoff with corpus counts.
