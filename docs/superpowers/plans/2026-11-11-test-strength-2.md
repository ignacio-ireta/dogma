# Plan: I-34 Test strength, second pass: machine probes for what hand-written wrong solutions miss

*Written and executed on 2026-11-11, after I-32 (the first pass,
[2026-11-09-test-strength.md](2026-11-09-test-strength.md)) and I-33 (real datasets in every
test). The numbers are in
[docs/audits/2026-11-11-test-strength-2.md](../../audits/2026-11-11-test-strength-2.md). The
rules this pass added are in [CONTENT_SPEC §6.7 and §6.8](../../CONTENT_SPEC.md). This file says
what the first plan could not find, how the second pass finds it, and how to run it again.*

## What the first pass could not see

I-32 gave every problem a blind solution, one hand-written wrong solution per Contract bullet and
a triage of one-token mutants. Its own report names four limits:

- **A cap of eight bullets per problem.** 87 bullets were never probed. Most of them are the
  last bullet, "must not mutate".
- **One mistake per bullet, the one the author thought of.** A not-mutated test that catches
  `x -= x.mean()` says nothing about `x.sort()`.
- **Shared test objects.** A module-level dict that every test passes to the learner can already
  carry an earlier test's damage. About 22 files had one, and they were not audited.
- **Mutants are edits of the reference.** A reference that returns an array can never be mutated
  into one that returns a list of the same numbers.

I-33 then replaced the data of every hidden test. Its gate checked the sampled mutants and the
recorded wrong solutions. It did not ask what real data hides that nobody had recorded.

## The idea: wrap the reference, change one thing

A probe is the reference solution plus a wrapper. The result stays right, and exactly one
property is broken, so a probe that passes every test proves that no test checks that property.
Three families, all generated by `scripts/exercise_probe.py`:

| Family | The wrapper | Finds |
|---|---|---|
| `scribble` | Returns the right result, then changes one argument in place: sorts it, centres it, rescales it, takes absolute values, rounds it, writes into a nested item, adds a key | Not-mutated tests whose input the change does not move, or that check another argument, or that run on an object already damaged |
| `returns` | Hands the right values back in a laxer form: a list for an array, float32 for float64, a float for an int, a one-element array for a float, a detached tensor, a reversed list or frame | Returns bullets that no test checks, because comparing values accepts the laxer form |
| `needs_array`, `needs_float` | Fails for one valid form of an argument: a list, an integer array | A wrong solution for `add-test` once `record` has shown that no passing call gets that form |

Before any grading, `record` runs the tests on the reference with a recorder as the submission
and notes, for every argument: its container, size, dtype, sign, ties, order, and whether the
call succeeded or raised. It also tries every in-place change on a copy of every argument and
counts the calls on which the change **would show**. That count splits the scribble survivors:

- **The change shows on a tested input, and nothing notices.** A gap wherever the Contract says
  inputs are not mutated. No judgement is needed.
- **The change never shows on a tested input.** Either the domain rules it out (the absolute
  value of a probability) or the tests never give that kind of value. The Contract decides.

## Rules this pass added

1. **A not-mutated test passes NumPy arguments read-only.** Any write then fails, so one test
   closes every in-place change at once, including the ones no probe tried.
2. **A not-mutated test builds its input inside the test and checks after one call.** Two calls
   that reverse a list restore it.
3. **A type the Contract names is checked by type.** `12.0 == 12`, and `assert_allclose` accepts
   a list.
4. **A differentiable function says so, and a test compares gradients.** 28 PyTorch problems
   never gave the learner a tensor that requires gradients. A solution that leaves the graph
   passed all of them.
5. **A missing Contract sentence is written first, as a new last bullet.** The gate then runs
   against a snapshot (`--base "$(git stash create)"`). Editing an existing bullet breaks the
   manifest entries that quote it.
6. **One version bump per problem per program.** The tool counts from the newest tag in
   `START_TAGS` (`i34-start` for this pass).
7. **An `uncovered` entry is dropped when a reject covers its clause** (`prune-uncovered`).

## Runbook

Every command runs from the repository root. `OUT` is a scratch directory under `var/`.

```bash
P="uv run --frozen --group torch python"
OUT=var/audit-i34/probe

# 1. What do the tests give each argument, and which in-place changes would show? (2 minutes)
$P scripts/exercise_probe.py record --out $OUT

# 2. Grade the probes on the learner's real path (about 25 minutes on 6 workers).
$P scripts/exercise_probe.py returns  --out $OUT --workers 6
$P scripts/exercise_probe.py scribble --out $OUT --workers 6

# 3. Read the candidates.
$P scripts/exercise_probe.py report --out $OUT
```

For each survivor, decide with this table, top to bottom:

| Question | If no |
|---|---|
| 1. Does a Contract bullet promise the property, in words? (`exercise_gate.py clauses ID`) | `note --kind unpromised`. If the property matters to a caller, write the sentence first (rule 5), then go on |
| 2. Is the broken property one a learner could plausibly break? An int that equals the promised float, or a list where the statement writes `(a, b)`, is not | Leave it. Say so in the report |
| 3. Does the reference, and does every accept variant, keep the property? | That is a finding about the reference or the statement. Stop and report it |

Three yeses: write one test of at most 40 lines, save the probe as the wrong solution, and let
the tool do the rest.

```bash
$P scripts/exercise_probe.py write --out $OUT <id> <probe> <cand>/reject_<what>.py
$P scripts/exercise_gate.py add-test <id> <cand>/new_test.py --out var/audit-i34/coord \
    --wrong <cand>/reject_<what>.py --mistake "<plain words>" --clause <label>
```

`add-test` appends the test, bumps the version, runs the whole gate (the reference twice, every
accept, every recorded reject, the wrong solution on the old and the new tests, five other
seeds, the run time) and records the wrong solution, or restores every file.

Then, for the problems that changed, grade their probes again and check that the survivors are
gone. Finish with:

```bash
$P scripts/exercise_gate.py prune-uncovered --out var/audit-i34/coord
$P scripts/exercise_gate.py variants --out var/audit-i34/final
$P scripts/exercise_gate.py lint     --out var/audit-i34/final
$P scripts/exercise_audit.py seeds   --out var/audit-i34/final
$P scripts/exercise_audit.py mutate  --out var/audit-i34/final
make check
make test-all
```

## What was left out on purpose

- **A tuple returned as a list** where the statement writes `(a, b)`: a caller that unpacks
  cannot tell. The same for an `int` returned where a whole-valued `float` is promised, and for
  a tuple where a list is promised.
- **In-place changes that never show on a valid input** of that argument: the absolute value of
  a probability vector, a float-only change on an array of labels.
- **A differentiability sentence for functions that are not trained through:** optimiser steps,
  a hand-written backward pass, position tables, a sampling filter, a cached decoding step.
- **The 102 `message-defect` rows of I-32** (a wrong solution that sees a bare exception) and
  the numbered ids of 35 problems. They are about what the learner reads, not about what the
  tests catch. They stay in `docs/audits/test-strength-decisions.md`.
- **SQL problems and class entries.** A wrapper needs one function call to wrap. 26 problems.

## Limits

- A probe proves that a property is unchecked. It does not prove the property matters: the
  Contract and question 2 decide that.
- The recorder's classes are a fixed list (empty, one row, negative, zero, ties, order, list or
  array, integer dtype, frame index). A class nobody listed is not reported.
- A problem whose test counts executed Python lines fails under the recorder, which adds lines.
  One problem (`dl/building-tensors-by-broadcasting/p01`) is skipped for that reason.
